本项目是 PPT Master Studio。PPT/PPTX 创建、转换、美化、模板、动画、图片与质量检查均使用 GitHub 中的 PPT Master Studio；旧的 Harness ZIP、复制到 Project 的 Authority/Workflow/Regression 文件不再作为当前源码 authority。

【唯一源码 Authority】
Repository: dycm8009/ppt-master-studio
Stable branch: studio-main
Development branch: studio-dev
Upstream mirror branch: main

【新 PPT 启动】
1. 开始任何 PPT 工作前，先从 GitHub 解析 studio-main 当前 HEAD 的完整 40 位 commit SHA；随后本项目整个生命周期锁定该 SHA，不继续追踪移动中的 studio-main。
2. 读取该 SHA 下的 studio/VERSION.json 与 studio/PROJECT_BOOTSTRAP.md。
3. 将该精确 commit 的仓库内容物化到当前运行环境；不得用另一 commit 的本地副本替代。优先使用 GitHub commit archive / checkout，并记录实际 repo root。
4. 读取该 commit 下 skills/ppt-master/SKILL.md，运行官方 attribution_guard；再读取 studio/enforcement/PPT_MASTER_AUTHORITY.md、PPT_MASTER_WORKFLOW.md、PPT_MASTER_TEMPLATE_RULES.md、PPT_MASTER_REGRESSION_POLICY.md。serverless/ChatGPT 宿主还必须读取 PPT_MASTER_STATIC_UI_RULES.md 与 PPT_MASTER_RECOVERY_RULES.md。
5. 运行：python3 studio/scripts/enforced_bootstrap.py --repo-root <repo-root> --running-commit <PINNED_SHA>。失败即停止，不得绕过。
6. 读取官方 skills/ppt-master/workflows/routing.md，选择且只选择一个顶层工作流；官方 workflow 是执行核心，Studio 文件只叠加宿主适配与质量策略。
7. 创建 project_state.json checkpoint，并写入 repository=dycm8009/ppt-master-studio、ref=studio-main、commit=<PINNED_SHA>。后续阶段继续使用这个 SHA。

【已有 PPT / 新聊天 / 环境重置】
8. 优先读取 project_state.json。若存在 harness.commit，必须加载该精确 commit，而不是当前 studio-main 最新 HEAD。
9. 若 project_state.json 或工程目录因运行环境重置而丢失，先寻找/要求最近一次 *.ppt-recovery.zip，校验 manifest 与 SHA-256 后恢复，再运行 enforced_preflight.py <project> --running-commit <PINNED_SHA>。
10. Recovery Bundle 自带 Harness commit binding；没有有效 Recovery Bundle 且真实必需工件已丢失时必须 Fail Closed。不得根据聊天记忆伪造 project_state、spec_lock、accepted receipts、SVG 或 QA 结果。
11. 只有用户明确要求升级一个正在进行的项目时，才允许做 Harness migration；不得静默把旧项目升级到 studio-main 最新版本。

【ChatGPT 静态交互】
12. Default Generate 的用户决策闭环在 ChatGPT 中使用 Studio Static UI Adapter：Stage 1（Communication + Template）→ Stage 2（Final Deck Plan）→ Deck Review；Custom Motion 被激活时增加 Motion Review。HTML 仅做本地交互并输出 JSON，用户回传后必须用 static_ui_adapter.py validate 生成 accepted receipt，不能凭聊天文字假定 Gate 已通过。
13. Stage 1/2 面向用户的固定 UI 应随用户语言本地化；canonical IDs/enum 保持官方值。Stage 2 三套方向必须提供整页视觉样本；Visual Style、Mode、Icons、Image Strategy 必须提供各自适合的视觉/语义反馈，不能退化为仅文字+色板。

【长 Deck / 图片 / 动画 / QA】
14. 18 页及以上执行 Studio Deck-level Art Direction：Deck Rhythm、Composition Diversity、Primary Visual Carrier、Section Personality、Similarity Gate；默认同一构图连续不超过 2 页，禁止“标题+卡片”万能回退。
15. 图片依次经过 Image Opportunity → Semantic Necessity → Template Compatibility → Image Role Fitness → Treatment & Placement；图片不是多样性配额，0 张图片合法。General + Dark Tech 默认 SVG-native，禁止 ambient/full-bleed raster/AI 背景和 dense HUD 概念图，除非真实证据型图片确有必要并放在明确内容容器中。
16. 长 Deck 禁止 deck-wide auto animation；默认 transition none，章节边界可克制 fade；对象动画只服务讲解顺序并受 Motion Budget。Breathing/Anchor 页面默认静态。
17. 最终导出前完成官方 SVG Quality Gate，并按 Studio 策略完成 Render Review、Deck Diversity/Similarity Audit、图片兼容性审计（如有）、Motion Audit（如有）、PPTX Postflight。Beautify/Convert 默认保持原始内容、事实与页序，除非用户明确授权改写。

【GitHub 分支纪律】
18. main 保持 upstream 镜像；studio-main 只放通过回归的稳定 Studio Overlay；studio-dev 用于修改和测试。普通 PPT 永远不使用 studio-dev，除非用户明确要求测试开发版。
19. Studio 修改先进入 studio-dev，GitHub Actions regression 通过后用 PR 晋升到 studio-main。ZIP 只可作为发布/离线恢复产物，不再是源码 authority。
