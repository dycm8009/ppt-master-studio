# Engineering Editorial — Design Specification

## I. Template Overview

| Application context | Definition |
| --- | --- |
| Recurring presentation family | 工程技术分享、架构评审、研发方法培训、系统方案说明与内部技术讨论 |
| Intended audiences and outcomes | 面向研发工程师、Tech Lead、架构师和技术管理者；帮助受众快速理解复杂系统、识别关键判断与证据，并形成可执行的讨论或决策 |
| Delivery and reading assumptions | 以现场讲解为主、会后阅读为辅；页面强调结论型标题、低文本密度和可独立理解的工程图形 |
| Representative narrative/page roles | 当前原型覆盖封面、价值/Why、目录、章节、系统地图、双路径对比、证据/判断链、要点回顾与 Q&A；具体选页、顺序和重复方式由当前项目的 Strategist 按内容决定 |

- 视觉采用暖白背景、深墨蓝结构骨架、钴蓝事实/能力、琥珀橙风险与 Gate、青绿验证通过的有限语义色。
- 强调“技术白皮书的严谨 + 编辑设计的留白 + 工程架构图的表达”，避免霓虹、玻璃拟态、密集 HUD、大面积卡片墙和无语义装饰。
- 默认不用照片或 AI 背景；主要视觉载体为 SVG 原生系统图、判断链、证据链、边界图和少量线性图标。
- 结构上分为 Engineering Editorial Anchor 与 Engineering Editorial Content 两个 Master 家族：Anchor 服务封面、章节、回顾与 Q&A 的高留白节奏页；Content 服务价值、目录、系统图、对比和流程页。

## III. Typography

| Role | Font stack | Application |
| --- | --- | --- |
| Chinese headings | `"Microsoft YaHei", Arial, sans-serif` | 结论型标题、章节标题 |
| Chinese body | `"Microsoft YaHei", Arial, sans-serif` | 正文、注释、表格 |
| Latin labels | `Arial, "Microsoft YaHei", sans-serif` | Agent、Skill、Gate、命令名、短标签和页码 |

字体采用常见系统字体栈，不打包或分发字体文件。中文为主；只有 Agent、Skill、Harness、OpenSpec、命令名、缩写和确有工程语义的 Gate 等术语保留英文。

## IV. Signature Design Elements

- 暖白画布与 60 px 左右的稳定外边距形成编辑版式基线。
- 左上角“蓝点 + 短线”作为轻量识别元素；不使用公司 Logo 或组织名称。
- 标题优先写结论句，正文每页只承载一个主要判断；大图形承担信息组织，文字仅做必要标签。
- 结构色与语义色严格分工：蓝色表示事实/能力，橙色表示风险/判断关口，绿色只用于验证和完成。
- 章节/转折页保留呼吸感，但使用有语义的 SVG 主视觉而不是单个巨大符号。
- 内容页根据材料在系统图、路径对比、证据链、任务/架构图等构图之间切换；避免连续两页使用相同构图。
- 图片策略默认为 none；只有真实证据型图片确有必要时才放入明确内容容器。
